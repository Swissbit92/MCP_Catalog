## Next (this month)

- [ ] **Tool brain (ADR-008 P1 + TB5) soak monitoring** — `TOOL_BRAIN_ENABLED=true` LIVE on prod since 2026-07-05. Single-model native tool-calling loop scoped to the web lane (router scopes surface, model decides within); wallet stays deterministic; media-find (`_MEDIA_SEARCH`) narrows to the single image/video tool for reliable firing. Revert: `TOOL_BRAIN_ENABLED=false` + `launchctl kickstart -k gui/$(id -u)/com.nephilim.backend`. See [ADR-008](decisions/008-two-brain-split-tool-brain-voice-brain.md).
- [ ] **Groundedness gate (ADR-007) soak monitoring** — `GROUNDEDNESS_GATE_ENABLED=true` LIVE on prod since 2026-07-04 (user-requested soak); monitor real conversations for false-abstention before treating as permanently on. Revert: flag off + `launchctl kickstart -k gui/$(id -u)/com.nephilim.backend`.
- [ ] **Relevance gate (`SEARCH_RELEVANCE_GATE_ENABLED`) go/no-go** — tuned to `SEARCH_RELEVANCE_MIN_COSINE=0.36` against an n=25 eval set (2026-07-04, extended same-day from n=8 with 17 real Brave query/result pairs): catches 100% of junk with a 5% false-abstention rate, and the one false-abstention is a synthetic adversarial sample, not real data. ## Later (exploratory)

- [ ] **Retire the ADR-004 two-stage agentic pipeline** (`argument_extractor.py` + `agentic_pipeline.py` + the Stage1/Stage2 split) — **superseded by the ADR-008 single-model tool brain.** The pipeline existed only because Magidonia couldn't native-tool-call; the tool brain replaces its purpose and the `interceptor`/`injection_guard` it shared are REUSED (do NOT delete those). It's inert (`AGENTIC_ENABLED=false`, never on in prod), so keeping it costs nothing and it's a pure-win cleanup with zero urgency. **Do NOT delete before the ADR-008 soak holds** (~1 week of real Telegram use, no tool-brain regressions). Deferred deliberately (2026-07-05): deleting superseded, safety-adjacent code the same day its replacement shipped is a bad trade. When retiring: delete the pipeline + `argument_extractor`, keep the shared interceptor/guard, re-run the tool-call red-team, mark [ADR-004](decisions/004-persona-safe-agentic-tool-calls.md) Superseded.
- [ ] **ADR-009 later phases — layered toolkit beyond web** ([ADR-009](decisions/009-layered-toolkit-registry-generic-web-toolset-inner-wisdom-skills.md)). The registry + web toolset shipped; these remain "when-you-want-them", **one at a time, after the tool-brain + ADR-006 memory soaks settle** (don't compound unverified surface). Recommended order: **(a) inner-wisdom (memory-as-tools)** — read-only memory retrieval as a tool, BUT **now BLOCKED on the ADR-006 per-persona injection framing rework** (2026-07-06): memory-as-tools *is* memory injection by another name, and the abliterated eval showed injection homogenizes voice (EEVA 0.75→0.25) — so inner-wisdom would hit the identical failure and cannot sensibly start until that framing is reworked and re-gated on abliterated. **(b) SKILL.md skills** — progressive-disclosure capability files. **(c) sandboxed terminal — LAST, and only with a serious sandbox design.** Giving an abliterated, no-refusal-floor model shell access is the highest-stakes item in the whole roadmap; it needs a real isolation boundary, not a quick add. None solves a current pain — driven by felt need, not a checklist.

Unblocks BOTH memory re-entry (flip `MEMORY_CONTEXT_INJECT`/`MEMORY_FACTS_ENABLED` back on) AND ADR-009 inner-wisdom, which both hit the same homogenization wall on abliterated. - [ ] **Known gap — strategy position tracking is a no-op** (surfaced 2026-06-23 during the MongoDB-removal doc reconciliation). When the MongoDB dual-write was removed, position open/close events and HITL approval decisions became **log-only** — the former `open_positions` / `approval_decisions` collections were not re-homed to SQLite. As a result `StrategyService.has_open_position()` always returns `False` (fail-open), so the double-entry guard is effectively disabled and the HITL audit trail isn't persisted. **Harmless while the wallet/strategy execution path isn't trading live** — but it MUST be wired to SQLite (a `wallet_positions` table + `record_trade`-style writes) before that path goes live. See the note in [architecture/WALLET_METADATA.md](architecture/WALLET_METADATA.md) (Trade Persistence) and [ADR-002](decisions/002-remove-mongodb-mcp.md).
